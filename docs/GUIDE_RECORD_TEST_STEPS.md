## 📋 Test 1: DRAFT作成テスト（STAFF）

### 目的
- STAFF権限でDRAFT状態のガイド記録を作成できることを確認
- 「下書き」バッジが正しく表示されることを確認

### 手順

1. **ブラウザでアクセス**
   ```
   https://localhost:3443
   ```

2. **ログイン**
   - NextAuth.jsのサインイン画面が表示されるはず
   - もしテストユーザーが存在しない場合は、新規ユーザーを作成
   - メールアドレス: `staff@example.com` (推奨)
   - または任意のメールアドレスで新規登録

3. **利用者一覧にアクセス**
   ```
   /recipients
   ```
   - もし利用者が存在しない場合:
     - 「利用者登録」ボタンをクリック
     - 最低限の必須項目を入力:
       - 氏名: 山田 太郎
       - 氏名カナ: ヤマダ タロウ
       - 生年月日: 1990-05-15
       - 性別: 男性
     - 保存して利用者IDを控える

4. **利用者詳細画面にアクセス**
   ```
   /recipients/[利用者ID]
   ```

5. **ガイド記録タブをクリック**
   - URL: `/recipients/[利用者ID]/guide`
   - 一覧画面が表示される

6. **「ガイド記録登録」ボタンをクリック**
   - URL: `/recipients/[利用者ID]/guide/new`
   - 作成フォームが表示される

7. **必須項目を入力**
   ```
   開始日時: 2026-03-03 10:00
   終了日時: 2026-03-03 12:00
   外出先: 〇〇公園
   目的: 散歩
   移動手段: 徒歩
   支援内容: 散歩の付き添い
   ```

8. **「下書き保存」ボタンをクリック**
   - 一覧画面にリダイレクトされる
   - 作成した記録が表示される
   - 状態バッジが「下書き」（灰色）で表示される

### ✅ 期待される結果
- ✅ DRAFT状態のガイド記録が作成される
- ✅ 一覧画面に「下書き」バッジ付きで表示される
- ✅ 「編集」「提出」「削除」ボタンが表示される

### ❌ 失敗時の切り分け
- **エラーメッセージが表示される**: コンソールログを確認（F12 → Console）
- **保存ボタンが押せない**: バリデーションエラーを確認
- **リダイレクトされない**: ネットワークタブでAPIレスポンスを確認

## 📋 Test 2: DRAFT→SUBMITTED遷移テスト

### 目的
- DRAFT→SUBMITTEDの状態遷移が正常に動作することを確認
- 提出後は編集ボタンが無効化されることを確認

### 前提条件
- Test 1で作成したDRAFT記録が存在

### 手順

1. **ガイド記録一覧にアクセス**
   ```
   /recipients/[利用者ID]/guide
   ```

2. **作成した記録の「提出」ボタンをクリック**
   - 確認ダイアログが表示される

3. **「OK」をクリック**
   - 状態バッジが「提出済み」（青色）に変わる
   - 「編集」ボタンが非表示または無効化される
   - 「提出」ボタンが非表示になる

### ✅ 期待される結果
- ✅ DRAFT→SUBMITTEDに状態遷移する
- ✅ バッジが「提出済み」に変わる
- ✅ 編集ボタンが使用不可になる
- ✅ `submittedAt`, `submittedBy`が記録される（DB確認）

### ❌ 失敗時の切り分け
- **ボタンがクリックできない**: 権限エラーの可能性（コンソール確認）
- **状態が変わらない**: tRPC mutationのエラーを確認
- **編集ボタンが残る**: GuideRecordWorkflowActionsコンポーネントの条件分岐を確認

## 📋 Test 3: ServiceRecord自動生成の確認

### 目的
- GuideRecordのSUBMIT時にServiceRecordが自動生成されることを確認
- guideRecordIdで1:1紐付けがされていることを確認

### 前提条件
- Test 2でSUBMITTED状態に遷移した記録が存在

### 手順

1. **サービス提供実績一覧にアクセス**
   ```
   /service-records
   ```

2. **Test 2で提出した記録に対応するServiceRecordを探す**
   - 利用者名: 山田 太郎
   - サービス提供日: 2026-03-03
   - 開始時刻: 10:00
   - 終了時刻: 12:00

3. **ServiceRecordをクリックして詳細を表示**

4. **以下の項目が正しく同期されているか確認**
   ```
   ✅ serviceDate: 2026-03-03
   ✅ startTime: 10:00
   ✅ endTime: 12:00
   ✅ duration: 120分（自動計算）
   ✅ destination: 〇〇公園
   ✅ purpose: 散歩
   ✅ serviceDetail: 散歩の付き添い
   ✅ guideRecordId: ガイド記録のIDが紐付いている
   ```

### ✅ 期待される結果
- ✅ GuideRecordのSUBMIT時にServiceRecordが自動生成される
- ✅ guideRecordIdで1:1紐付けがされている
- ✅ データが正しく同期されている
- ✅ durationが自動計算されている（120分）

### ❌ 失敗時の切り分け
- **ServiceRecordが存在しない**:
  - tRPCルーター `guideRecord.submit` の実装を確認
  - `src/server/routers/guideRecord.ts` の `submit` mutationを確認
- **データが同期されていない**:
  - ServiceRecordのupsert処理を確認
  - guideRecordIdの設定を確認
- **durationが正しくない**:
  - `calculateDuration` 関数の実装を確認

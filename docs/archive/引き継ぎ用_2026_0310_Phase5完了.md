#### 主要機能

1. **月次締め処理**
   - 事業所・年月単位での締め処理
   - 締め実行者・日時の記録
   - 締め理由のメモ機能

2. **差戻し機能**
   - 締め後の差戻しが可能
   - 差戻し実行者・日時・理由を記録
   - 差戻し後は再度編集可能

3. **ロック機構**
   - 締め処理済み月は全ての更新系操作を制限
   - 対象操作:
     - シフト作成・更新・削除・公開
     - 打刻修正・削除
     - 承認申請・承認処理
   - エラーメッセージ: "YYYY-MMは既に締め処理済みです。修正するには差戻しが必要です。"

4. **CSV出力**
   - 職員別・日別の勤怠データをCSV出力
   - ヘッダー: `職員名,日付,曜日,出勤,退勤,休憩(分),実働(時間),残業(時間),深夜(時間),休日(時間),備考`
   - UTF-8 BOM付き（Excel対応）
   - ファイル名: `attendance_YYYY-MM_[unitId].csv`

5. **UI機能**
   - 事業所選択ドロップダウン
   - 年月選択（カレンダー）
   - サマリー表示（対象職員数、総出勤日数、総実働時間）
   - 締め履歴表示（タブ切替）
   - 締めステータス表示（締め日時・実行者）

## 1. システム概要

福祉・介護分野における重度障害者支援の業務日誌・記録システム。日々の支援記録、バイタルサイン、ヒヤリハット、申し送り事項などを一元管理し、利用者のQOL向上と支援の質の向上を目指す。

### 1.1 システムの主軸（Plan → Do → Fact → Safety + Attendance）

| レイヤ                 | 内容                     | 対応機能                  | ステータス |
| ---------------------- | ------------------------ | ------------------------- | --------- |
| **L1: Plan（計画）**   | 個別支援計画             | 利用者管理・印刷帳票      | ✅ 完了 |
| **L2: Do（実施）**     | 日々の支援記録・業務日誌 | ガイド記録・業務日誌      | ✅ 完了 |
| **L3: Fact（実績）**   | サービス提供実績         | ServiceRecord（自動生成） | ✅ 完了 |
| **L4: Safety（安全）** | 事故・ヒヤリハット       | インシデント管理          | ⚠️ スキーマのみ |
| **L5: Attendance（勤怠）** | 職員勤怠管理・月次締め | 打刻・シフト・月次締め    | ✅ 完了 ⭐ NEW |

## 5. データベース構成

### 5.1 主要テーブル

```
User (職員)
├── role: STAFF / LEAD / MANAGER
├── (1:N) → CareRecipient (利用者)
│           ├── (1:1) → Assessment（段階的廃止予定）
│           ├── (1:N) → GuideRecord（ガイド記録）
│           │           └── (1:1) → ServiceRecord（自動生成）
│           ├── (1:N) → DailyLogEntry（業務日誌明細）
│           └── deletedAt（論理削除）
├── (1:N) → Shift ⭐ NEW
├── (1:N) → TimeClockEvent ⭐ NEW
├── (1:N) → AttendanceRecord ⭐ NEW
└── (1:N) → ApprovalRequest ⭐ NEW

Unit (ユニット)
├── (1:N) → UnitStaff（職員紐付け）
├── (1:N) → UnitRecipient（利用者紐付け）
├── (1:N) → DailyLog（業務日誌ヘッダー）
│           └── (1:N) → DailyLogEntry
└── (1:N) → MonthlyClosing ⭐ NEW

ShiftType ⭐ NEW
└── (1:N) → Shift

AuditLog (監査ログ)
└── action: View/Edit/Delete/Approve/BackToDraft
```

### 5.2 重要な注意事項

- **論理削除**: `deletedAt`で論理削除。物理削除は原則禁止。
- **5年保存**: サービス提供記録は提供した日から5年間保存。
- **Assessment段階廃止**: CareRecipientにSSoT統合済み。
- **月次締めロック**: MonthlyClosingレコードが存在する月は更新不可（差戻しを除く）⭐ NEW

## 14. Phase 5 実装の技術的ポイント

### 14.1 月次締めロック機構

**実装方針**:
- `assertMonthNotClosed` ヘルパー関数で一元管理
- 全ての更新系tRPCプロシージャで呼び出し
- 締め処理済み月へのアクセス時は `TRPCError` をスロー

**適用箇所**:
```typescript
// src/server/routers/shift.ts
await assertMonthNotClosed(prisma, unitId, shiftDate, userId);

// src/server/routers/timeClock.ts
await assertMonthNotClosed(prisma, unitId, eventDate, userId);

// src/server/routers/approval.ts
await assertMonthNotClosed(prisma, unitId, targetDate, userId);
```

### 14.2 CSV出力のExcel互換性

**実装ポイント**:
- UTF-8 BOM (`\uFEFF`) をヘッダー行に付与
- 文字エンコーディング: `utf8`
- tRPC query endpoint 経由でダウンロード

```typescript
const BOM = '\uFEFF';
csvRows.push(
  BOM + '職員名,日付,曜日,出勤,退勤,休憩(分),実働(時間),残業(時間),深夜(時間),休日(時間),備考'
);
fs.writeFileSync(outputPath, csvContent, { encoding: 'utf8' });
```

### 14.3 Neon + Prisma 7 接続設定

**重要な知見**:
- Prisma CLI（`db push`, `migrate`）は pooler 非対応
- `DIRECT_URL` に `connect_timeout=30&pool_timeout=30` を追加

    process.env["DATABASE_URL"],
},

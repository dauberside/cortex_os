  - `DATABASE_URL` = Neon pooler URL
  - `DIRECT_URL` = Neon direct URL
- `prisma.config.ts` で datasource の優先順位を変更し、現在は `DATABASE_URL` を `DIRECT_URL` より先に見るように修正済み
- 以前は `DIRECT_URL` が優先されていて、エラーの接続先ホストは direct endpoint 側だった

   - `DATABASE_URL` 側にも問題があるのか

4. Neon 構成として
   - pooler を Prisma の `db push` で使って問題ないか

## Prisma / Neon 接続調査メモ

### 判明した事実
1. `DATABASE_URL`（pooler）
   - Node.js の `pg` ドライバおよび Neon Serverless Driver では接続成功。
   - アプリケーション通常利用の接続先としては有効と判断できる。

2. `DIRECT_URL`（direct）
   - `pg` ドライバで TLS ハンドシェイクエラーが発生。
   - Prisma の `db push` や migration 系が利用したい direct endpoint 側に問題がある可能性が高い。

3. Prisma の動作
   - `DATABASE_URL` / `DIRECT_URL` のどちらを優先しても Prisma では `P1001` が発生。
   - pooler は通常クエリでは動作していても、`db push` のような DDL 操作では安定しない、または非対応の可能性がある。

4. Prisma 7.x の設定方針
   - `schema.prisma` での `url` / `directUrl` 定義を増やすより、`prisma.config.ts` 側で datasource を管理する方針で整理する。
   - 現状の主論点は schema の書き方ではなく、実際の接続先の到達性である。

5. `.env` の見直し
   - `sslaccept=accept_invalid_certs` は不要パラメータとして削除済み。
   - ただし direct endpoint 側の接続問題は未解決。

### 現時点の結論
- 根本原因は **Neon の direct endpoint への接続失敗** の可能性が高い。
- `.env` の `DIRECT_URL` が古い、または Neon 側で endpoint 状態が変化している可能性がある。
- 一時的に `DATABASE_URL` 優先へ寄せる回避はあり得るが、`db push` / migration 系の恒久対応としては非推奨。

### 次のアクション
1. Neon ダッシュボードで direct endpoint の状態を確認する。
2. 最新の direct connection string を再取得し、`.env` の `DIRECT_URL` を更新する。
3. 更新後、`psql` などで `DIRECT_URL` の疎通確認を行う。
4. その後 `pnpm db:push` を再実行して Prisma の接続可否を確認する。
5. 必要に応じて Neon と Prisma 7.x の互換性情報も確認する。

### 引き継ぎメモ
- `DATABASE_URL` はアプリ用接続先として有効だが、Prisma の DDL 系操作の解決策にはなっていない。
- 重点確認対象は `prisma.config.ts` よりも **Neon 側の direct endpoint と最新 connection string**。
- 今後の対応では、Prisma 設定変更だけで解決しようとせず、Neon 側設定確認を前提に進めること。
